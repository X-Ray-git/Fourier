# Android 说明

Android 正在按现有 macOS 设计语言做类比迁移，但不是照搬 AppKit 实现。

平台边界：

- `AppGlassSurface`、`AppGlassCompactSwitch` 等纯 Flutter 组件可以跨平台复用；`NSGlassEffectView`、窗口后方取样和红黄绿等 AppKit 能力仍只属于 macOS。
- 少量固定浮动控件可以使用真实 Flutter 模糊玻璃；时间线卡片等密集重复元素继续使用轻量外壳，避免重演 macOS 列表玻璃造成的性能回退。
- package id 已迁移到 `io.github.xraygit.autofolo`。安装签名 key 不同但包名相同的 APK 会和现有安装冲突；GitHub 内部构建使用已约定的签名设置。

截至 2026-07-16 已完成的迁移：

- 主时间线只在 header 暴露 `未读/全部`，复用 `AppGlassCompactSwitch`。Android 参数为轨道 `55 x 29`、滑块宽 `40`、透明点击区 `48`、外框 `0.6px / 55%`；视觉左边界与卡片统一为 `12px`。
- 底部主导航改为图标式悬浮胶囊：水平边距 `12px`、高度 `48px`、底部 `SafeArea + 8px`。保留页面淡入淡出；选中项延续清晰的橙色反馈。外阴影通过路径差集只绘制在胶囊外侧，不能透进半透明导航内部。
- 最近阅读从主导航移到订阅源页，并作为二级时间线进入。
- 文章页已使用圆形玻璃已读按钮；存在目录时在其上方显示目录按钮，目录使用共享移动端玻璃底部面板。正文底部空间按是否存在目录动态避让。
- 订阅源详情改为紧凑 header，阅读状态筛选与主时间线一致；自动全文、翻译和静默设置进入共享玻璃底部面板。
- `AppMobileGlassSheet` 是移动端玻璃底部面板的共享外壳，当前统一圆角 `32px`、水平边距 `8px`、底部 `viewPadding + 8px`。不要在目录和订阅源设置中分别复制这些参数。
- 普通卡片、骨架、空态继续复用 `ArticleCardChrome` 的布局基线；本轮没有把密集卡片改成重型玻璃。

已修复的响应式陷阱：

- `SubscriptionsController.unreadFor()` 必须先读取 `_unreadCounts[feedId]`，再根据静默状态决定是否返回零。旧实现对静默源提前返回，导致外层 `Obx` 没有读取任何 Rx：Debug 显示 GetX 红色错误，Release 则表现为 Inbox 展开后从左侧滑入的大块灰色区域。
- 不要把该问题误判为 `AnimatedCrossFade` 或页面淡入淡出故障；为排查做过的替换已经撤销，原有动画保留。

当前尚未完成：

- 设置页、后台任务中心和其余次级页面仍需按同一边界继续迁移。
- 等 Android 几何参数视觉稳定后，再根据目标设备外形反推屏幕、浮动导航和底部面板的同心圆关系。Android 没有可靠的通用 API 直接返回物理屏幕圆角，不能把当前视觉值写成设备真值。

验证清单：

- 主时间线、订阅源详情的 `未读/全部` 筛选正确，左侧与卡片对齐。
- 底部导航三页切换、选中反馈和淡入淡出正常，阴影不污染内部。
- Inbox 展开没有灰色块或 GetX 红色错误。
- 最近阅读入口、文章目录、已读按钮和订阅源设置面板可用，正文不会被浮动控件遮住。
- 深色和浅色模式下控制边界、文字和底部导航均可辨认。
- 设置导入/导出和文章图片预取仍正常。
